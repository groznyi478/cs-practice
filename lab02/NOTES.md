Рабочая папка — это файлы проекта, которые находятся у меня на компьютере.
Индекс — промежуточная область между рабочей папкой и историей Git.
Коммит — это сохранённая точка в истории проекта.
Git — это программа для отслеживания изменений в коде на вашем компьютере, а GitHub — это сайт в интернете для хранения этого кода и командной работы
git diff - изменения в рабочей папке, которые не были добавлены с помощью git add, а git diff --staged - добавленные изменения, которые попадут в следующий коммит
Использованные команды:
1. git status
Показывает текущее состояние рабочей директории и индекса.
2. git diff
Показывает изменения в рабочей директории, которые ещё не добавлены
в индекс.
3. git diff --staged
Показывает изменения, подготовленные в индексе для следующего коммита.
ветка:
Ветка — это отдельная линия разработки проекта.
При создании новой ветки она начинается с текущего состояния проекта.
После создания ветки новые коммиты могут существовать только в этой ветке
и не появляются автоматически в main.

Слияние веток выполняется с помощью команды git merge.

     Сравнение команд

git diff
Показывает различия между состояниями файлов.

Обычно git diff показывает изменения, которые есть в рабочем каталоге,
но ещё не были закоммичены.

git show
Показывает конкретный коммит: его сообщение, автора и изменения, которые этот коммит внёс.

git log
Показывает историю коммитов.

git log -S"def"
Ищет коммиты, в которых изменилось количество вхождений строки `def`
в указанном файле.

git blame
Показывает, какой коммит отвечает за появление каждой строки файла.

   Восстановление файла

git restore lab03/calc.py восстанавливает файл из текущего `HEAD`.

git restore --source=HEAD~2 lab03/calc.py восстанавливает файл из
конкретного старого коммита, указанного после --source 

При этом история коммитов не изменяется. Изменяется только содержимое
файла в рабочей директории.

Если бы после git restore --source=HEAD~2 я сделал git add и git commit,
старое содержимое стало бы частью нового коммита. Без commit история
остаётся прежней.
 Revert

git revert HEAD не удаляет ошибочный коммит.

Он создаёт новый коммит, который отменяет изменения предыдущего.

Это особенно удобно для опубликованной истории, потому что старые коммиты
остаются на месте.

git reset --hard работает иначе: он перемещает HEAD и может убрать
коммиты из текущей ветки, а также удалить незакоммиченные изменения.

Поэтому для отмены уже опубликованного ошибочного коммита обычно используют git revert, а не переписывают историю через reset --hard.
 
 Tag и branch

Tag — это имя, привязанное к определённой версии проекта.
Например, v1.0 обозначает конкретное рабочее состояние.

Branch — это указатель на развивающуюся линию истории. Новые коммиты
продолжают двигать ветку вперёд.

Поэтому v1.0 можно использовать как постоянную отметку версии,
а main продолжает развиваться.

  Экспериментальная ветка
Ветка experiment использовалась для безопасного добавления
деления с проверкой деления на ноль.
Изменение было сделано не непосредственно в main.
После проверки ветка была объединена с main командой:
   git merge --no-ff experiment
Опция --no-ff` заставила Git создать отдельный merge-коммит,
сохранив факт существования экспериментальной ветки в истории.
